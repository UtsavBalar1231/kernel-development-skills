For videos, pages, and other visual work, avoid the stock AI aesthetic: dark gradient backgrounds with blurred color blobs, dot grids, glassy pill badges, glowing highlights, gradient or per-letter animated titles, bouncy spring pop-ins, and the default Inter plus macOS traffic-light window look. Prefer one concept tied to the product and executed with restraint: few elements, each with a job, one accent color used only for annotation, ease-out motion, hard cuts.

**Why:** the user rejected a polished dark motion-graphics walkthrough as "AI generated slop" and accepted a printed-field-guide design (flat paper page, serif headings, the real terminal as a captioned figure, numbered margin notes) on 2026-10-12. They also want real material over reconstructions: real terminal sessions, not summary cards.

Keep on-screen text to a minimum, and never label footage as "real", "unedited", "exactly as pasted", or "recorded in a fresh home": the user called those labels "crap" on 2026-10-12. Let the footage show it. The cut that followed kept only titles, chapter number and title, short numbered margin notes (3-6 words), and an "N× speed" tag; it dropped decks, phase captions, figure numbers, the contents page, the three-point summary, and the recording footer.

**How to apply:** before building visuals, pick a concept from the product itself, build one style frame, and check every element for a job before propagating. Show real artifacts (terminal recordings, actual output) rather than designed summaries of them, without captions that vouch for them. Before adding any line of text to a frame, ask whether the picture already says it. Related: [[project-publishing-channels]], [[feedback-kernel-skill-voice]]
